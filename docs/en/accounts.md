# Accounts and sign-in

No service without a login: QuietBoard shows nothing without signing in.

## First start

On the first start there is no account yet. The app writes a **setup code** to the log (and `install.sh` shows it). Whoever knows it creates the first admin account at `http://<server>:8088`:

```bash
docker compose logs status | grep Einrichtungscode
```

The code is valid until the first account exists; after a restart there is a new one.

## Roles

| Role | May |
| --- | --- |
| **Admin** | everything: add hosts, users, settings, jobs, pause checks, test the morning digest |
| **Viewer** | see everything, change their own password, push on their own devices |

Create users under **System → Users**. Passwords: at least 10 characters, stored with scrypt. After 10 failed attempts sign-in is blocked for 15 minutes. Sessions last 30 days.

Healthchecks and Beszel have their own admin logins: `ADMIN_EMAIL` and `ADMIN_PASSWORD` from `.env`.

## Language

The interface is available in German and English. It follows the browser language; switch it under **System → Account → Language** (applies to this browser).

Messages generated by the server – morning digest, push, mail, Signal and “Needs attention” – have their own setting: **System → Notifications → Language of messages** (admins; default German, preset with `LANGUAGE=en` in `.env`).

## API tokens for your own scripts

Under **System → API tokens** every user creates tokens for their own scripts (e.g. for Home Assistant or a dashboard). A token has the same rights as the account – a viewer's token can only read.

```bash
curl -H "Authorization: Bearer qb_…" http://<server>:8088/api/state
```

The token is shown only once; only a checksum is stored. The list shows when a token was last used. *Revoke* blocks it immediately. Admins also see and revoke other users' tokens. When a user is deleted, their tokens stop working.

Not to be confused with the access key for hosts (`INGEST_TOKEN`), which hosts use to send their reports.

## Forgot password, admin locked out

The emergency CLI in the container helps:

```bash
cd ~/quietboard
docker compose exec status python -m tools.cli users
docker compose exec status python -m tools.cli passwd you@example.org     # generates a new password
docker compose exec status python -m tools.cli role you@example.org admin
docker compose exec status python -m tools.cli add new@example.org --role admin
```

## Cloudflare Access (optional)

If QuietBoard sits behind Cloudflare Access, Access can handle sign-in: set `ACCESS_TEAM` (team name) and `ACCESS_AUD` (application audience tag) in `.env`. Whoever passes Access is an admin. Local accounts keep working.
